# Three.js 视频制作

## 触发与输入

适用于完整视频制作，以及已有视频的内容、画面、声音和字幕修改。单纯讨论问题、撰写综述或制作静态插图不进入这条流程。

先读取项目规则、当前计划、原始素材、现有成片及相关源文件。提取以下输入；已有对话明确的信息直接沿用：

| 输入 | 决定什么 |
|---|---|
| 核心内容与目标 | 影片要传达或论证的对象 |
| 受众已有知识 | 哪些内容需要展开，哪些可直接使用 |
| 事实或学术主张状态 | 涉及可证伪的主张时见 [evidence-rigor.md](references/evidence-rigor.md)；否则跳过 |
| 语言、声音、字幕 | 配音路线、版本数量、字幕布局 |
| 时长与交付规格 | 内容范围、画幅、分辨率、最终文件 |
| 已有产物及本次变更 | 起始阶段和需要失效的下游产物 |

信息不足时先完成不依赖它的核查。只对会改变范围或接口的缺口提问。

## 制作原则

1. **理解目标先于动画。** 每段用一个观众应能获得的结果定义目标，再设计解释和画面。
2. **内容依赖先于章节顺序。** 前置内容在首次使用前建立；已知内容简述，需要展开的内容明确展开。
3. **涉及事实或学术主张时，证据与表达分开。** 旁白、公式、画面和引用连线表达同一强度的主张；动画不能把假设表现为已经验证的规律。具体做法见 [evidence-rigor.md](references/evidence-rigor.md)；不涉及此类主张的内容跳过这条。
4. **分镜先于批量制作。** 先确定对象、变化、解释与反例，再编写场景和合成全片语音。
5. **音频实测决定时间。** 每个语言有自己的时间轴；译文跟随配音语言，画面读取同一时间轴。
6. **状态只有一个写入者。** 生成文件由其构建器重建；编辑原始输入，而非同时修改多份派生内容。
7. **样片验证制作链。** 先验证一个代表性段落的解释、声音、字幕和最终编码，再扩展全片。
8. **观察先于验收。** 数值检查、视觉检查和试听各自记录证据；通过其中一项不能替代其余项。

## 结构与状态归属

以下路径相对视频项目根目录。已有项目保留其接口，先建立对应关系；新项目按职责创建实际需要的文件。

| 模块 | 唯一写入者 | 拥有文件 | 其他模块读取 |
|---|---|---|---|
| 制作范围与当前任务 | 协调流程 | 项目 `plan.md` 中的视频部分 | 目标、范围、规格、阶段 |
| 内容设计 | 内容编排 | `content/storyboard.md` | 内容依赖、画面事件；涉及主张时另含主张依据 |
| 各语言文案 | 脚本编写 | `content/story*.json` | 旁白、显示文本、逐句翻译 |
| 语音 | 配音构建器 | `build/<lang>/audio/sentences/`、`voice-provenance.json` | PCM 与声音来源 |
| 音画时序 | 音频构建器 | `build/<lang>/timeline.json` | 章节和字幕时间 |
| 配乐与混音 | 混音构建器 | `build/<lang>/audio/` 下混音产物 | 最终音轨 |
| 几何与版式 | 场景实现 | `src/` | 显式 `draw(t)` 接口 |
| 视频交付 | 导出与编码器 | `build/renders/`、`output/` | 成片、封面帧与外置字幕 |
| 缺陷与复核结论 | 审查步骤 | `build/<lang>/qa/review.md` | 问题位置、返工阶段、关闭证据 |

这些是职责，不要求创建对应数量的代理。审查先独立记录问题，再由相应模块修订。同一执行者可以依次承担不同职责。

## 接口与执行前置

新片或内容逻辑修改时读取[内容与文件契约](references/content-contracts.md)；涉及事实或学术主张时另读[主张与证据严谨性](references/evidence-rigor.md)，不涉及时跳过。先完成以下文件映射：

`问题 → 模块结构 → 文件接口 → 数据流 → 实现文件 → 可观测任务`

计划声明本次修改文件、输入前提和验证方法。现有素材足以确定的常规选择直接落地；阶段完成后继续，不将每个阶段变成审批点。

涉及音画实现时读取[制作技术参考](references/production-pipeline.md)。

已有项目若维护了自己的"项目实现映射"参考（具体文件、运行环境、工具入口），那是项目自己的内容，放在该项目下的 `.claude/skills/threejs-video/references/project-implementation.md`，不属于本模板；复用现有工具前先读它，它不能作为换文案即可生成任何主题的通用模板。

## 执行阶段

| 阶段 | 输入 | 操作与输出文件 | 进入下一阶段的依据 |
|---|---|---|---|
| P0 范围与映射 | 用户目标、素材、已有项目 | 更新 `plan.md`：问题、模块、接口、数据流、文件、任务；判断是否涉及需校准强度的主张；修改任务确定起点 | 目标、已知/未知、文件归属清楚 |
| P1 内容分镜 | 范围、原始素材 | `content/storyboard.md`：内容依赖、每段目标、画面事件；涉及主张时另含主张身份与依据 | 无未解释的必要前置；涉及主张时，引用支撑表述强度 |
| P2 脚本与分句 | 分镜、语言要求 | `content/story*.json`：旁白、画面文本、分句译文；核对关键术语 | 各语言表达一致；旁白与画面事件可对应 |
| P3 代表样片 | 脚本片段、环境 | 局部语音、场景、字幕、配乐、编码样片；测量与审查记录 | 已实际检查复杂术语、拥挤画面、视觉解释和同步 |
| P4 全量语音与时序 | 已验证的样片方案、全量脚本 | 语音片段、provenance、`timeline.json`、SRT、混音 | 片段对应正确；时序与译文观测已解释；声音有检查记录 |
| P5 全片场景与预览 | 分镜、时间轴、已验证的场景方案 | `src/` 与全章预览；章节关键事件及最大文字密度处截图 | 画面执行分镜；公式、字幕、对象关系可读且正确 |
| P6 导出与编码 | 经检查的预览、音轨、时间轴 | 浏览器渲染、MP4、封面帧、章节元数据、实际成片抽帧 | 文件存在、流正确、时长与输入一致；进入成片审查 |
| P7 审查与修订 | 成片、源文件、检查输出 | 按[审查协议](references/review-protocol.md)记录问题，回到所属阶段修订，再复核受影响输出 | 交付缺陷已关闭；未观察事项明确披露 |
| P8 交付与整理 | 已复核的成片、字幕与记录 | 更新播放入口、项目状态，提供最终媒体与封面帧链接 | 交付文件与源版本对应，不覆盖此前已交付版本；用户能打开和播放 |

样片选择最能暴露风险的片段，不固定为第一章。时长遵循内容和需求：硬上限通过缩减范围或分层讲解满足；不能靠不自然的语速和信息堆叠掩盖超时。

## 审查回边

审查记录包含 `issue_id / location / observation / evidence / return_to / affected_outputs / status`。具体格式见[审查协议](references/review-protocol.md)。

- 前置内容缺失、类比冒充推论 → P1；更新分镜后重写相应文案。
- 定义、翻译或术语错误 → P2；判断配音是否变化再重建。
- 音色、发音、分句变化 → P3/P4；对应语言的时间轴与下游音画失效。
- 图形关系错误、字幕遮挡 → P5；文案不变时复用语音。
- 输出加速、错误音轨、截尾 → P6；根据输入时长与时间戳查因。

审查提出的问题要有可定位证据。修订只处理已确认的缺陷；若发现目标、模块边界或接口必须变化，先更新计划。对依赖缺失、身份不明或无法获得必需证据的情况按项目停止条件处理。

## 观测与完成

技能自带只读工具 [observe_timeline.py](scripts/observe_timeline.py)：

```text
python <skill目录>/scripts/observe_timeline.py --timeline <视频目录>/build/en/timeline.json --require-translation
```

输出输入校验和、章节和字幕数量、时间区间问题、译文缺失及章节归属。普通单语版省略译文选项。它不检查发音、画面语义或最终编码，不能独立批准交付。

修改任务按[修改影响矩阵](references/production-pipeline.md#修改影响矩阵)选择最早受影响阶段，保留有效缓存，重建依赖产物。审查结论必须对应当前文件版本，不能沿用旧片的检查结论。

完成记录至少包含：每个交付文件的路径与版本、流信息和时长、实际检查的画面/试听区间、完整解码结果、已关闭问题、尚未验证项。内容正确性或可播放性缺陷未解决时，不将视频标成已验收。能力不足导致的听感等未观察项如实交代。
