# 内容与文件契约

## 使用范围

P1/P2 使用本文建立分镜和脚本接口。已有项目以实际解析器为准；下文字段存放在分镜中，不直接注入旧播放器接口。仅改声音、字幕排版时复用原内容设计，无需补造整套文档。

涉及事实或学术主张时，另读[主张与证据严谨性](evidence-rigor.md)；不涉及时跳过，不影响本文其余部分。

## 分镜：content/storyboard.md

分镜拥有内容设计和画面依据；最终逐字旁白只归属 `story*.json`，避免出现两份不同的配音稿。

### 全片结构

```text
核心问题：影片最终回答或传达什么？
受众起点：哪些内容已知，哪些需要现场建立？
主线：现象/问题 → 必要内容 → 机制 → 方法 → 结论与边界。
内容依赖：内容 ID → 前置内容 ID；每个前置标为受众已知或首次建立章节。
术语表：内容 ID、中文、英文、显示符号、旁白读法。
```

主线按实际主题调整。内容依赖用于解释顺序；涉及主张时另见 evidence-rigor.md 的文献关系图，两种图各自声明边的含义，不要混用。

### 每章接口

| 字段 | 内容 |
|---|---|
| `chapter_id` | 与各语言脚本和场景注册一致的稳定 ID |
| `question` | 本章结束后观众应达成的具体结果 |
| `requires` | 前置内容 ID，以及在哪里已经建立 |
| `teaching_sequence` | 直觉 → 准确定义 → 可操作例子 → 边界/反例 → 后续用途；已知环节可省略并说明依据 |
| `claims`（可选） | 涉及事实或学术主张时填写，见 [evidence-rigor.md](evidence-rigor.md) |
| `visual_events` | 事件 ID、旁白语义锚点、显示对象、对象变化、需要保留的前态、落点 |
| `outcome_check` | 观众应能辨认的差别，或能完成/回答的一件具体事情 |
| `next` | 下一章为什么需要本章的内容 |

### 示例：度量怎样改变球的形状

```text
chapter_id: metric-ball
question: 为什么同一平面的开球可以是圆盘，也可以是菱形？
requires: 点、集合、正半径；在前一章建立。
teaching_sequence:
  直觉：邻近是按指定规则测量的。
  定义：d 满足四条度量公理；Bε(x) = {y : d(x,y) < ε}。
  例子：同一组平面点，分别计算欧氏距离和曼哈顿距离。
  边界：边界点满足等号，所以不属于开球。
  用途：通过开球连接“距离”与下一章的开集。
visual_events:
  e1：讲到中心和半径时，先显示中心、候选点与距离标注。
  e2：讲到欧氏距离时，逐点显示是否满足 d < ε，再出现圆盘。
  e3：讲到另一种度量时，保持中心和 ε，替换判据并出现菱形。
  e4：点移到边界，用空心点和等式说明不包含边界。
outcome_check: 观众能否指出改变的是距离规则，并解释边界为何排除？
```

图形变形不能暗示两种距离数值相等。动画要呈现判据的变化；只有圆变菱形的装饰性过渡无法完成这一解释。

对抽象对象只显示有限示意。例如可数基的画面显示有限子族，旁白和标签应说明它是示意，不能以画面中几个集合充当整个可数性的证明。

## 语言脚本：content/story*.json

当前项目读取以下结构。新项目可以简化，但先同步声明接口与消费者。`subtitle_zh` 只在英文配音配中文字幕时需要；`source` 只在涉及主张时需要。

```json
{
  "title": "影片标题",
  "subtitle": "副标题",
  "voice": "已验证的音色 ID",
  "rate": 1.0,
  "scenes": [
    {
      "id": "metric-ball",
      "chapter": "基础内容",
      "title": "度量决定开球的形状",
      "eyebrow": "章节标签",
      "formula": "Bε(x) = {y : d(x,y) < ε}",
      "points": ["显示要点"],
      "narration": "待合成的完整旁白。",
      "source": "涉及主张时：来源标识及位置，或分镜中的主张 ID",
      "music": "math",
      "subtitle_zh": ["与实际英文分句逐条对应的中文译文"]
    }
  ]
}
```

多语言通过 `scene.id` 对齐内容；允许逐句表达与时长不同。章序变化同时更新场景映射和音频缓存身份。显示的公式与旁白读法分开处理，但不得改变含义。

分句函数是配音和字幕共同依赖。翻译数组长度等于实际分句数量；数学缩写、小数、引文中的句点需实际查看分句结果。若只有翻译变化，语音片段有效；若分句变化，即使完整旁白字面相同也要核对片段缓存。

## 时间轴：build/<lang>/timeline.json

生成接口的最小结构如下；章节可携带从脚本复制的显示字段。

```json
{
  "language": "en",
  "duration": 10.0,
  "chapters": [
    {"id": "metric-ball", "start": 0.0, "end": 10.0, "index": 0}
  ],
  "captions": [
    {"start": 0.3, "end": 4.0, "text": "A metric defines distance.", "translation": "度量定义距离。"}
  ]
}
```

数值为有限实数，单位秒。章节 ID 唯一；章节按播放顺序排列；普通字幕要求实际可见区间有正时长且不重叠。章间/句间留白合法。源区间若为延长显示而重叠，必须声明播放器的选取规则，并核对 SRT 是否使用相同可见区间。跨章字幕需要明确解释，不能自动截断掩盖错位。

语音采样时长决定句子区间；前后留白在构建器中显式加入。视觉事件锚定对应句子或其内部进度，再生成实际秒数。不能把全章任意等分作为与旁白同步的证据。当前项目采用章节内进度动画，是否需细化到句子由分镜的同步要求决定；新增字段前先修改接口计划。

## 渲染接口

约定画面入口接受 `draw(timeSeconds)`，时间来自同一语言时间轴。几何对象负责形状和变换；图文层负责字体、公式、标签和字幕；播放器负责时钟、跳转和录制。

每个事件明确可见开始和结束状态。相机运动用于解释空间关系；讲解公式或关键关系时留稳定视图。把动画停在任意关键时间，画面应能表达当前关系；随机数、累计积分和异步字体加载不能使重录出现不同结果。

采用渲染倍率时，倍率作为输出元数据交给编码器。音频仍使用自然时间。最终 MP4 的实际时间戳是检查对象。
