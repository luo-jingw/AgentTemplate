# 调研 / 进展报告（卡片式）

## 触发

用于把一段时间的调研结论、训练/实验进展、方法对比做成一份可独立打开、可翻页查看的报告。不用于单次简短问答、单张图（见 `diagram-svg`）、或正式出版物排版（那是 Word/PDF 的事）。

## 总体原则

1. **一页只回答一个问题。** 继承 `diagram-svg` 的核心原则，应用到页面层级：封面交代范围和结论，之后每页一个子问题，不要把多个不相关的结论堆进同一页。
2. **数字标来源和截止时间。** 任何统计数字、图表、进度百分比都要能回答"这是什么时候测的、从哪来的"；封面或图表下方写明"数据：xxx，截至 YYYY-MM-DD HH:MM"。这是 `AGENTS.md` → Validation / Constraint Provenance 原则在报告层面的体现。
3. **已观测、外推、假设性情景三者分开。** 曲线图里实线=已观测数据，粗虚线=按当前速度外推的投影，细点线=需要额外前提才成立的替代情景（例如"若恢复原速"）。三种线型的含义固定，不要挪用。
4. **状态徽章表达可验证性，不表达"好坏"。** `pill` 只回答"这件事能不能被验证/复现"（已确认/有条件/无法验证/中性），不要用它暗示优劣评价。
5. **嵌入的结构图遵循 `diagram-svg` 的颜色语义和网格规范。** 不要在报告里另起一套配色含义；两者共用同一组 CSS 变量。
6. **宽屏窄屏共用同一份 HTML。** 不要为了"演示模式"单独做一份文件；响应式切换已经内置在模板里。

## 接口与参考

- [页面结构](references/deck-structure.md)：封面、翻页、宽屏/窄屏双模式、打印与无障碍行为。
- [内容组件](references/content-blocks.md)：统计块、状态徽章、表格、kv 列表、进度卡片的markup 约定和使用场景。
- [曲线图引擎](references/charts.md)：数据形状、配置字段、对数轴何时用、悬浮提示、三种线型的具体用法。
- [deck-template.html](assets/deck-template.html)：可直接复制修改的起始文件，已包含可运行的演示数据；替换成真实内容时保留引擎函数本体不变。

## 执行

1. 复制 `assets/deck-template.html` 到报告输出位置。
2. 按 [页面结构](references/deck-structure.md) 规划每页回答的问题，決定要多少页。
3. 按 [内容组件](references/content-blocks.md) 选用统计块/表格/徽章/kv/进度卡片，删掉模板里用不上的示例内容。
4. 需要曲线图时，按 [曲线图引擎](references/charts.md) 把 `D`/`RUNS`/`CH` 换成真实数据；函数本体（`lineChart`/`progChart`/`niceTicks`/`logTicks` 等）不要改。
5. 需要结构图时，按 `diagram-svg` 的规范画，嵌进对应页面的 `<figure>`。
6. 用无头浏览器分别在宽屏（演示模式）和窄屏（滚动模式）、浅色和深色下过一遍，确认翻页、图表悬浮、徽章颜色都正常。

## 交付前检查清单

- [ ] 每页标题能一句话说清这页回答什么问题。
- [ ] 每个统计数字、图表、进度百分比都标了数据来源和截止时间。
- [ ] 曲线图里的实线/粗虚线/细点线用法符合"已观测/外推/替代情景"的固定含义，没有挪用。
- [ ] 状态徽章（`pill`）只表达可验证性，没有被当成好坏评价在用。
- [ ] 嵌入的结构图颜色含义和 `diagram-svg` 一致，没有另起一套。
- [ ] 宽屏演示模式：翻页按钮、键盘方向键、滚轮、触摸滑动都能翻页；进度条与页码正确。
- [ ] 窄屏滚动模式：卡片依次滚动可读，不依赖翻页按钮。
- [ ] 浅色、深色模式下对比度和可读性都没问题。
- [ ] 删掉了模板里没用到的示例内容（不要留着"方法 A/机构 X"之类占位文字）。
