# 结构图绘制（SVG）

本规范用于绘制论文或项目的结构图：扁平、模块化、每张图只回答一个问题、用颜色表达语义、深浅色自动适配。规则本身是自洽的，不需要找到或参照任何外部文章作为来源。

## 触发

用于需要绘制模型/系统结构图、模块关系图、数据流图、对比图等技术性图示的场合，交付形式是会被浏览器渲染的 HTML（Artifact 或网页）。目标是无法渲染 CSS 变量的静态图（论文插图、PNG 等）时，按本文末尾"导出静态图"处理，不要直接把这段 HTML 交出去。

## 总体原则

1. **大结构模块化，小结构单独放。** 先画一张总览图，只显示模块和主数据流；每个值得展开的子结构（内部细节、条件路径、输入编码、掩码规则等）各画一张独立的图。总览图里不要出现子结构的细节。
2. **一张图只回答一个问题。** 例如"数据怎么流过模型"、"一个模块里面是什么"、"两种方法有何不同"。如果一张图需要回答两个问题，就拆成两张。
3. **颜色表达语义，而不是装饰。** 同一类模块用同一种颜色；全文统一一套颜色含义（见 [视觉规格](references/visual-spec.md)）；每张图最多用 3–4 种颜色，并在图底写一行图例。
4. **框内文字极简。** 框内只放"标题 + 一行副标题"；副标题写关键数字或性质，不超过约 14 个汉字。解释性文字放在图注或正文里。
5. **数字要准确。** 维度、层数、数量等必须来自代码或原文，并在正文的表格里给出出处，图上只放最关键的。
6. **扁平。** 不用渐变、阴影、发光、3D、图标或插画；圆角矩形 + 细线 + 箭头即可。

## 接口与参考

- [视觉规格](references/visual-spec.md)：画布网格、颜色语义表、元素规格。先画前必读。
- [常见图型模板](references/templates.md)：八种常见图型（总览、模块内部、条件分叉、输入编码、矩阵对比、计算量对比、时间轴、流程）的具体画法，按需选用。
- [代码骨架](references/code-skeleton.md)：可直接复制修改的 HTML/CSS/SVG 起始代码，以及图注与正文的写法约定。

## 导出静态图

配色方案通过 CSS 变量加 `@media (prefers-color-scheme)` 自动适配明暗模式，前提是输出会被浏览器渲染（Artifact、网页）。交付目标是论文插图、PNG 等静态图像时，不支持 CSS 变量，按以下步骤处理：

1. 确定用浅色还是深色模式交付（论文插图通常用浅色）。
2. 把用到的 CSS 变量替换成该模式下的具体色值（见 [视觉规格](references/visual-spec.md) 颜色表）。
3. 用无头浏览器以该模式渲染后截图导出，不要凭记忆手工重画颜色。
4. 需要排入 PDF 时，给 `figure`、`table` 加 `break-inside: avoid`，固定浅色配色导出，避免图表被分页截断。

## 交付前检查清单

- [ ] 所有元素都在 x 40–640 之内，viewBox 高度贴合内容。
- [ ] 同一行的框之间至少留 18～20 的水平间距，没有重叠。
- [ ] 每条箭头都不穿过与它无关的框或文字；需要绕行时用 L 形折线。
- [ ] 每个框内文字都没有溢出（按[视觉规格](references/visual-spec.md)估算宽度）。
- [ ] 只用了 12px 和 14px 两种字号。
- [ ] 颜色含义与全文一致，并有一行图例；屏蔽 / 丢弃的位置同时用虚线表示。
- [ ] 每张图都有图注，且只回答一个问题。
- [ ] 用无头浏览器（如 Playwright）分别以浅色和深色模式对每个 `<figure>` 截图检查一遍。
- [ ] 需要 PDF 时，给 `figure`、`table` 加 `break-inside: avoid`，固定浅色配色导出。
