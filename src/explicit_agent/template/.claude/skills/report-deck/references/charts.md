# 曲线图引擎

模板自带两个画图函数：`lineChart`（通用多系列折线图，比如训练损失）和 `progChart`（专用于"进度 + 预测完成时间"这一种图）。两者都是纯 SVG 绘制，不依赖任何图表库。

## 数据形状

```js
var D={
  cfgA:{loss:[[0,2.1],[5000,0.9],[10000,0.55]]},   // [x, y] 对，按 x 升序
  cfgB:{loss:[[0,2.0],[5000,0.95],[10000,0.6]]}
};
```

每个系列（run / 配置）一个键，键下再按"线名"分组；同一个系列可以有多条线（比如一条平滑后的线 `loss`，一条原始单点 `loss_raw`，见下）。`D` 是唯一数据源，`RUNS`/`CH` 只是告诉引擎去 `D` 里取哪些键、怎么画。

## lineChart：配置字段

```js
var RUNS={demo:[['cfgA','s-a','配置 A'],['cfgB','s-b','配置 B']]};
var CH={'demo-loss':{runs:'demo',line:'loss',log:1,xmax:25000,xstep:5000}};
```

- `runs`：指向 `RUNS` 里的一组 `[D 的键, 颜色 class, 图例显示名]`。
- `line`：要画成平滑折线的那组点。
- `pts`（可选）：要画成半透明散点、叠在折线下面的原始单点测量——用于"线是平滑/EMA，点是单次真实测量"这种场景，图表头部要注明平滑方式（例如"EMA 0.95"），不要让读者误以为线本身就是原始数据。
- `log`（可选）：y 轴对数刻度，适合跨数量级的损失曲线；不设则是线性刻度，自动按 `niceTicks` 选整齐的刻度值。
- `y0`（可选）：线性轴强制从 0 开始（比如百分比/准确率这种有自然下限的指标）。
- `xmax`/`xstep`：x 轴（通常是训练步数）的范围和刻度间隔。
- `unit`（可选）：悬浮提示里数值的单位后缀，比如 `' dB'`。
- `end`（可选）：在每条线末端画一个强调圆点，标记"目前最新值在这里"。

HTML 侧只需要一个空 `<figure>`：

```html
<figure class="chart" data-chart="demo-loss" data-h="260"><div class="chart-h"><h3>标题</h3><span>说明</span></div></figure>
```

`data-chart` 对应 `CH` 里的键，`data-h` 是图表高度（像素，宽度固定自适应容器）。脚本启动时会扫描所有 `.chart[data-chart]`，按键值自动画图，不需要手动调用。

## 悬浮提示

鼠标移到图上时，自动在最近的 x 位置画竖直参考线、每条系列线的当前值圆点，并弹出一个跟随鼠标的提示框（系列名+当前值，若有 `pts` 还会额外显示"单次测量"原始值）。这是通用逻辑，不需要为新图表单独写。

## progChart：进度与预测

专门画"当前进度 + 预计何时到达目标"这一种图，不通过 `CH` 配置，`data-chart` 固定写 `"rt-prog"`：

```js
D.proj={
  rt_a:{now:<当前时间戳>,step:<当前步数>,eta:<预计完成时间戳>},
  rt_b:{now:...,step:...,eta:...,fastEta:<可选：乐观情景的预计完成时间>}
};
```

三种线型的含义**固定，不要互换**：

- **实线**：已经观测到的真实进度（当前实现里这条线退化为一个点——"当前进度"本身就是观测值；如果有完整历史轨迹，把它作为 `D[run].prog` 数组传入并画出真实折线，而不是只画一个点）。
- **粗虚线**：按当前速度外推到目标步数的投影，终点标实际预计时间。
- **细点线**（`fastEta` 存在时才画）：需要额外前提才成立的替代情景（比如"如果恢复到正常速度"），要在标签里写清楚这个前提，不能只写时间不写前提。

### 标签避让

预测终点的文字标签默认画在终点右上角；如果两条线的终点时间彼此靠得很近，`spreadLabels()` 会在绘制完所有标签后按实际测量的文字宽高（`getBBox()`，不是估算）检测重叠，把发生冲突的标签顺次向上错开一行，而不是任其压字。这个避让只处理"标签挤在一起"，不处理"数据点本身太密"——时间点之间的最小有效间距仍然取决于图表宽度和数据本身，标签避让不能替代选择合理的时间粒度。

## 首次进入的描边动画

`lineChart` 返回的折线会在首次进入视口时用 `stroke-dasharray`/`stroke-dashoffset` 做"从左到右画出来"的动画；散点和 `progChart` 里标了 `fade` class 的元素（预测线、预测终点、标签）延迟淡入，让读者先看到实际发生的部分，再看到预测部分。这两套动画都只触发一次，`prefers-reduced-motion: reduce` 时自动跳过，不需要额外处理。
